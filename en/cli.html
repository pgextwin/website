Choose a download command

By default, the CLI fetches the latest published releases registered in the Catalog. No GitHub API credentials are needed. ZIPs are saved in a new folder under your working directory; existing files are not overwritten.

Latest Catalog · all registered ZIPs
.\pgextwin.exe download-all --pg all
Latest Catalog · all registered PG18 ZIPs
.\pgextwin.exe download-all --pg 18
Fixed historical snapshot · 70 ZIPs
.\pgextwin.exe download-all --pg all --fixed
Verify separately obtained external original ZIPs offline (no provider GET)
.\pgextwin.exe verify-external-all --ledger .\evidence\issue112-external-pg18-direct-link-review-v1.json --input-dir C:\original-external --pg 18
Download the pg_trickle PG18 provider original (valid signed admission required)
.\pgextwin.exe download-all --source external --pg 18 --output C:\pgextwin-external --external-admission .\external\external-get-admission.json --external-bundle .\external\attestation.json

verify-external-all checks separately obtained ZIPs offline; its ledger is not GET authorization. For provider-original GET, save the signed admission JSON and Sigstore proof from the same issuer Run and specify an existing output folder. Expired, invalid or out-of-scope admissions are denied. Other external providers remain DOWNLOAD_DENY; mirror and redistribution remain MIRROR_DENY.

Latest Catalog support

View or save download progress

Opt-in UTC timestamped events report signed Catalog verification, every ZIP start, transferred bytes in 8 MiB intervals, SHA256 verification and batch completion. Diagnostic events go to stderr; normal stdout and JSON remain unchanged.

Download all registered ZIPs with live progress
.\pgextwin.exe download-all --pg all --verbose
Keep a detailed log file
.\pgextwin.exe download-all --pg all --verbose 2> download-verbose.log

Verbose output does not change trust: individual extension ZIPs remain INTEGRITY_ONLY. No install or extension publication privileges are added.

How it works / 動作のしくみ

How it works

The two download paths converge on the same original-ZIP integrity checks and atomic output. The displayed steps describe the CLI, not a Windows installer.

1 · Choose a source
LATEST

Latest (default)

Fetch the published Catalog selection feed and its Sigstore bundle over HTTPS, and verify the signer, source, commit and immutable Catalog records.

FIXED

Fixed (--fixed)

Use the immutable historical Catalog/policy snapshot pinned by the CLI, with its independently pinned SHA256.

  1. 2 · Select packages

    Choose the Catalog-registered Release tag and original ZIP for each requested PostgreSQL major. Never infer the upstream's latest tag.

  2. 3 · Download & check

    Fetch original GitHub Release ZIP bytes over bounded HTTPS; verify each SHA256 and reject mismatches, unsafe redirects and partial batches.

  3. 4 · Save & report

    Commit the verified set to a new output directory and write DOWNLOAD-INFO.json. Existing output is not overwritten.

    DOWNLOAD-INFO.json

What is (and is not) verified

SIGSTORE VERIFIED

CLI executable

GitHub Actions Sigstore-attested build; SHA256 of public EXE independently checked.

SIGSTORE VERIFIED

Catalog feed (latest mode)

Independent Sigstore verification of the feed and immutable Catalog byte hashes.

INTEGRITY_ONLY

Extension ZIPs

SHA256 integrity against authenticated/pinned metadata only: INTEGRITY_ONLY. Individual extension signatures/provenance and install authorization are not established.

The CLI is download-only; it does not install ZIPs, modify services, create a signed combined bundle, or make original extension publication decisions.

Release notes

English

CLI v0.3.8 — direct provider-original GET for pg_trickle PG18 and historical HypoPG 1.4.1 PG14–16. Only with an unexpired, owner-approved and independently Sigstore-verified admission, the CLI fetches the unchanged original ZIP directly to the user's machine and checks its size and SHA256. Expired or out-of-scope admissions remain DOWNLOAD_DENY. Offline verify-external-all is also available.

Published Windows x64 EXE: 12,892,708 bytes. Verified protected-main source 3ce07983ef0a93069b2b0ba850b9dc970e3f373f and public asset SHA256 aecb0537622148b46b731b543ce511ee281877f4e6fbc31c77f8346689ce6077. The public Windows EXE verified all 85 native Catalog ZIPs for 17 extensions.

Trust boundary: Individual external-provider ZIPs remain INTEGRITY_ONLY. No third-party ZIP mirroring, redistribution or installation. oracle_fdw and community pgvector remain on hold.
