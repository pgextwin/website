One-line usage

Default: newest release approved and registered in the Catalog; no GitHub REST API credentials required. ZIPs are written in a new folder under the working directory.

Latest Catalog · all registered ZIPs
.\pgextwin.exe download-all --pg all
Latest Catalog · 14 ZIPs, PG18 only
.\pgextwin.exe download-all --pg 18
Fixed historical snapshot · 70 ZIPs
.\pgextwin.exe download-all --pg all --fixed

New in v0.3.2

Live progress with --verbose

Opt-in UTC timestamped events report signed Catalog verification, every ZIP start, transferred bytes in 8 MiB intervals, SHA256 verification and batch completion. Diagnostic events go to stderr; normal stdout and JSON remain unchanged.

Download all registered ZIPs with live progress
.\pgextwin.exe download-all --pg all --verbose
Keep a detailed log file
.\pgextwin.exe download-all --pg all --verbose 2> download-verbose.log

Verbose output does not change trust: individual extension ZIPs remain INTEGRITY_ONLY. No install or extension publication privileges are added.

How it works / 動作のしくみ

How it works

The two download paths converge on the same original-ZIP integrity checks and atomic output. The displayed steps describe the CLI, not a Windows installer.

1 · Choose a source
LATEST

Latest (default)

Fetch the published Catalog selection feed and its Sigstore bundle over HTTPS, and verify the signer, source, commit and immutable Catalog records.

FIXED

Fixed (--fixed)

Use the immutable historical Catalog/policy snapshot pinned by the CLI, with its independently pinned SHA256.

  1. 2 · Select packages

    Choose the Catalog-registered Release tag and original ZIP for each requested PostgreSQL major. Never infer the upstream's latest tag.

  2. 3 · Download & check

    Fetch original GitHub Release ZIP bytes over bounded HTTPS; verify each SHA256 and reject mismatches, unsafe redirects and partial batches.

  3. 4 · Save & report

    Commit the verified set to a new output directory and write DOWNLOAD-INFO.json. Existing output is not overwritten.

What is (and is not) verified

SIGSTORE VERIFIED

CLI executable

GitHub Actions Sigstore-attested build; SHA256 of public EXE independently checked.

SIGSTORE VERIFIED

Catalog feed (latest mode)

Independent Sigstore verification of the feed and immutable Catalog byte hashes.

INTEGRITY_ONLY

Extension ZIPs

SHA256 integrity against authenticated/pinned metadata only: INTEGRITY_ONLY. Individual extension signatures/provenance and install authorization are not established.

The CLI is download-only; it does not install ZIPs, modify services, create a signed combined bundle, or make original extension publication decisions.

English

CLI v0.3.2 — live diagnostic progress. Use --verbose to follow Catalog Sigstore verification, individual download starts, 8 MiB transfer updates, SHA256 checks and completion of the selected ZIPs. Logs are on stderr; stdout and JSON contracts are unchanged.

The trim-compressed Windows x64 EXE is 12,829,662 bytes. Latest signed-Catalog and historical --fixed modes remain supported. Download failures still reject unsafe bytes, avoid overwriting existing output and fail closed.

Scope: The CLI executable and Catalog feed have their own verification; original extension ZIPs are INTEGRITY_ONLY, not individually Sigstore-authenticated. No installation or extension-release authorization is granted.
